# Initializing a new tree

These steps run once, when a project tree is created. The standing constraints live in `CONSTITUTIONS.md` beside this file.

## Static toolchain before implementation

Before any implementation, add the strictest available static toolchain to a script or CI check that rejects a failing change: a formatter, strict linting, and type checking with a deliberately curated ignore list. Python follows `PYTHON.md` beside this file, Rust and TypeScript follow the sections below, and another ecosystem uses its own equivalent.

In languages that allow both quote styles (Python, TypeScript, Shell), string literals and docstrings use single quotes, and the toolchain enforces that from the first commit. A string that would escape many single quotes of its own, or a shell string whose variables must expand, keeps double quotes.

### Rust toolchain and release profile

`cargo fmt` formats the code with its defaults, and clippy lints it at these levels in `Cargo.toml`:

```toml
[lints.rust]
warnings = 'deny'

[lints.clippy]
pedantic = { level = 'warn', priority = -1 }
```

The negative priority ranks the group below individual lints, so a later entry can relax one lint of the group.

`warnings = 'deny'` covers clippy's pedantic warnings as well, so `cargo build` stops at the first warning while developing. `RUSTFLAGS='--warn warnings' cargo build` relaxes that for one command.

A binary target generally adds:

```toml
[profile.release]
lto = true
strip = true
codegen-units = 1
```

### TypeScript toolchain

Prettier runs with `singleQuote: true`.

oxlint, with the `oxlint-tsgolint` package installed, runs the type-aware rules of typescript-eslint on typescript-go. oxlint has no preset that matches the strict typescript-eslint configurations, so `.oxlintrc.json` is generated by `@oxlint/migrate --type-aware --with-nursery` from an ESLint flat config that holds exactly typescript-eslint's `strictTypeChecked` and `stylisticTypeChecked` configurations and ESLint's `recommended` configuration. ESLint, typescript-eslint and the generator are installed only for that run. The generated file sets `options.typeAware` to `true` and turns off oxlint's own `correctness` category, and that `categories` entry is deleted to keep those rules on. typescript-eslint itself runs only on the JavaScript implementation of the TypeScript compiler, so a tree that lints with it cannot upgrade tsc to typescript-go.

tsc runs with `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `noImplicitOverride`, `noImplicitReturns`, `noFallthroughCasesInSwitch`, `noUnusedLocals` and `noUnusedParameters`.

## Supply chain cooldown

Every package manager in the tree that has a release age setting refuses dependency versions published within the last 15 days.

The uv setting is part of the pyproject skeleton in `PYTHON.md` beside this file.

pnpm, in `pnpm-workspace.yaml`, in minutes:

```yaml
minimumReleaseAge: 21600
```

pinact, which pins and updates GitHub Actions, in `.pinact.yaml`, in days:

```yaml
version: 3
min_age:
  value: 15
```

Cargo ignores `registry.global-min-publish-age` with a warning unless it runs under nightly `-Zmin-publish-age`, so a stable toolchain has no release age setting yet.

A version inside the window is admitted per package, through `exclude-newer-package`, `minimumReleaseAgeExclude`, or a pinact rule with `min_age: 0`.
